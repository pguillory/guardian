# dep-pass-2026-11-09: Debian trixie-20261104 and nimble_options 1.2.0

## Problem and change

A routine dependency pass on November 9, 2026, taking only versions published at
least 48 hours earlier. `mix hex.audit` reports no retired packages, and the GitHub
advisory database lists nothing against the versions in `mix.lock`. The base refresh
does close one build-time issue, the apt advisory below.

- The Debian base goes from `trixie-20261027-slim` to `trixie-20261104-slim` (published
  November 5) in `Dockerfile`. That moves both the builder image
  (`hexpm/elixir:1.19.7-erlang-28.5.0.8-debian-trixie-20261104-slim`) and the runner
  image (`debian:trixie-20261104-slim`). Both tags exist for amd64 and arm64.
- `nimble_options` (transitive, through Finch) goes from 1.1.1 to 1.2.0, published
  November 2. It is the only package in the `mix.lock` diff, and
  `THIRD_PARTY_NOTICES.md` names the new version.

Already current: Elixir 1.19.7 and Erlang/OTP 28.5.0.8 are each the newest on their
line, cloudflared 2026.10.7 is its latest release, and every other direct Hex package
is at its latest release.

## Held back

- `peri` 0.12.0 (transitive): Anubis 2.2.0, still its latest release, requires
  `~> 0.11.2`, so it moves with Anubis.
- `hypex` 2.x: held at 1.x for the reasons in `docs/architecture/system.md`, section
  10.
- Elixir 1.20.5 and Erlang/OTP 29: unchanged from
  [the previous pass](dep-pass-2026-11.md); each is a deliberate change of its own.

## Advisories checked

- Debian DSA-6613-1 (zlib, November 7: CVE-2026-27171, CVE-2026-76844,
  CVE-2026-85091) is newer than any base tag, so this image still carries the
  vulnerable `zlib1g`. No affected call path was found: the flaws are in
  `crc32_combine64` and the `gz*` file-writing API, Guardian has no compression code
  of its own, the Erlang `zlib` module uses deflate and inflate rather than those
  APIs, and cloudflared is a static Go binary. The next base refresh picks up the fix.
- Debian DSA-6607-1 (apt, November 4) lets a man-in-the-middle replace a package
  after verification during an HTTP download. In Guardian that is the `apt-get`
  steps of the image build, which use the base image's default HTTP sources; the
  running image doesn't use apt. `trixie-20261027` had the vulnerable apt, and
  `debian:trixie-20261104-slim` carries the fixed apt 3.0.4 (the debuerreotype
  `rootfs.manifest` for both amd64 and arm64), so this refresh closes it for the
  runner stage. The builder's apt was not checked separately; its hexpm image is
  built on the same Debian tag.

## Compatibility

Guardian itself is unchanged. `nimble_options` 1.2.0 adds a `:redact` option, accepts
maps where a schema expects a keyword list, and fixes wildcard-key schemas, exception
inspection with ANSI enabled and `nil` MFA validation. Finch, its only user here,
validates its pool configuration with schemas that have no wildcard keys, and Guardian
passes Finch no pool options of its own. The new release requires Elixir 1.15 or
later; Guardian requires 1.16.

## Product spec impact

None. No statements in `docs/product/overview.md` or `docs/product/spec.md` change.
