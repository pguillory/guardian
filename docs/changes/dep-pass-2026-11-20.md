# dep-pass-2026-11-20: plug 1.20.4, bandit 1.15, finch 0.25 and cloudflared 2026.11.1

## Problem and change

A routine dependency pass on November 20, 2026, taking only versions published at
least 48 hours earlier (by Hex's `inserted_at`, or the GitHub release time for
cloudflared). `mix hex.audit` reports one advisory, against `plug` 1.20.3 (see
[Advisories checked](#advisories-checked)), and no retired packages.

`mix.lock` changes:

- `plug` 1.20.3 to 1.20.4, published November 17: only the fix for that advisory.
- `bandit` 1.14.1 to 1.15.0, published November 16 (held back by
  [the previous pass](dep-pass-2026-11-16.md) as too new).
- `telemetry` 1.4.2 to 1.4.3, published November 16 (held back last pass).
- `nimble_pool` 1.1.0 to 1.2.0, published November 16 (held back last pass); Finch
  0.25 requires it.
- `finch` 0.24.0 to 0.25.0 (transitive, through Req and Anubis), published November
  17 (Pacific time), just over 48 hours before this pass. Both dependents allow it
  (`~> 0.21` and `~> 0.24`).

cloudflared goes from 2026.11.0 to 2026.11.1, released November 17. The version and
both per-architecture SHA-256 checksums in `Dockerfile` change together, keeping the
pin-and-checksum scheme. The checksums are the ones listed in the
[official release](https://github.com/cloudflare/cloudflared/releases/tag/2026.11.1),
and match the downloaded binaries. `THIRD_PARTY_NOTICES.md` names the new version.

`THIRD_PARTY_NOTICES.md`'s Hex table now matches `mix.lock` again. Two rows had
already drifted before this pass: `bandit` read 1.13.1 while the lock had 1.14.1, and
`plug_crypto` read 2.2.0 while the lock had 2.2.1.

The Debian base, Elixir and Erlang/OTP are unchanged: `trixie-20261104-slim` is still
the newest Debian tag on Docker Hub, for both `debian` and `hexpm/elixir`, and Elixir
1.19.7 and Erlang/OTP 28.5.0.8 are each still the newest on their line.

## Advisories checked

- `plug` 1.20.3: EEF-CVE-2026-120287 (CVE-2026-120287, GHSA-qj4r-jh2r-rw3f, medium).
  `Plug.Parsers.MULTIPART` didn't charge part and header framing against its
  `:length` limit. Not reachable in Guardian: the JSON API's only `Plug.Parsers` is
  configured with `parsers: [:json]`, and Anubis's MCP transport doesn't parse
  multipart bodies. Fixed in 1.20.4, taken here.
- Bandit 1.15.0's changelog credits GHSA-j9wq-h5xx-5qx5 for a fix: it logs the count
  of HTTP/2 trailers instead of their contents, since a small HPACK-compressed trailer
  section could cause large CPU use and log volume. `mix hex.audit` lists no advisory
  against 1.14.1, and the GHSA id wasn't public when this pass looked, so this pass
  makes no claim about its severity or whether Guardian's deployment was exposed. The
  fix arrives with the upgrade either way.
- cloudflared 2026.11.1 carries VULN-187395, an OpenTelemetry bump to 1.47.0. Its
  release notes don't describe the issue; this is an update for hygiene.
- Debian DSA-6613-1 (zlib) is still open in the image, with no affected call path, as
  described in [the November 9 pass](dep-pass-2026-11-09.md). Debian's fixed build
  still has no `debian` or `hexpm/elixir` tag on Docker Hub; the next base refresh
  picks it up.

## Compatibility

From the packages' changelogs:

- Bandit 1.15.0: connection processes hibernate after 15 seconds idle to release memory;
  response bodies under 300 bytes, and already-compressed content types, are no longer
  gzipped; HTTP/2 CONNECT handling and stream-identifier checks follow RFC 9113 more
  strictly; plus a `date` header on Bandit's own error responses, stricter HTTP/2
  `:method` and `:path` validation, and WebSocket fixes. None changes Guardian's API.
- Finch 0.25.0: on HTTP/2, `:receive_timeout` becomes an idle timeout (it used to bound
  the whole response), and `:request_timeout` bounds the whole response. Guardian's only
  HTTP client is the S3 client, which sets a 5-second connect timeout (so Req gives it a
  pool of its own), keeps Req's default HTTP/1 protocol, and leaves the request and
  receive timeouts at their defaults, so the HTTP/2 change doesn't apply. The rest are
  fixes, among them pools no longer copying their connection options into every process,
  and HTTP/2 pools no longer sticking after a GOAWAY.
- telemetry 1.4.3 adds `execute_lazy/2,3`; nimble_pool 1.2.0 is what Finch 0.25 needs.
- cloudflared 2026.11.1 reconnects when the account's region changes and lets quick
  tunnels fall back to HTTP/2
  ([release notes](https://github.com/cloudflare/cloudflared/blob/2026.11.1/RELEASE_NOTES)).

- `GET /health` returns 200, and a request without a key gets 401.
- An authenticated query and an MCP `tools/list` succeed, covering the new Bandit and
