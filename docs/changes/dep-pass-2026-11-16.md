# dep-pass-2026-11-16: cloudflared 2026.11.0

## Problem and change

A routine dependency pass on November 16, 2026, taking only versions published at
least 48 hours earlier. `mix hex.audit` reports no retired packages, and the GitHub
advisory database lists nothing against the versions in `mix.lock`; it has no new
Erlang-ecosystem advisories since [the previous pass](dep-pass-2026-11-09.md).

- cloudflared goes from 2026.10.7 to 2026.11.0, published November 12. The version and
  both per-architecture SHA-256 checksums in `Dockerfile` change together, keeping the
  pin-and-checksum scheme. The checksums are the ones listed in the
  [official release](https://github.com/cloudflare/cloudflared/releases/tag/2026.11.0),
  and match the downloaded binaries. `THIRD_PARTY_NOTICES.md` names the new version.

`mix.lock` does not change. The Debian base, Elixir and Erlang/OTP are unchanged:
`trixie-20261104-slim` is still the newest Debian tag on Docker Hub, and Elixir 1.19.7
and Erlang/OTP 28.5.0.8 are each still the newest on their line.

## Held back

- `bandit` 1.15.0, `telemetry` 1.4.3 and `nimble_pool` 1.2.0 were all published on
  November 16 (Pacific time), inside the 48-hour window. The next pass considers them.
- `peri` 0.12.0 (transitive): Anubis 2.2.0, still its latest release, requires
  `~> 0.11.2`, so it moves with Anubis.
- `hypex` 2.x: held at 1.x for the reasons in `docs/architecture/system.md`, section
  10.
- Elixir 1.20.5 and Erlang/OTP 29: unchanged from
  [the November 2 pass](dep-pass-2026-11.md); each is a deliberate change of its own.

## Advisories checked

- cloudflared 2026.11.0 is built with Go 1.27.4, which has security fixes in cgo, the
  go command, the compiler, the linker and `net/http`. It also carries VULN-170057
  ("Don't bypass access with matrix parameters"), a fix to Cloudflare Access
  validation. The `tunnel run` connector Guardian starts with a tunnel token is not
  expected to reach that validation (not verified against cloudflared's call graph),
  so this is an update for hygiene rather than an urgent fix.
- Debian DSA-6613-1 (zlib) is still open in the image, with no affected call path, as
  described in [the previous pass](dep-pass-2026-11-09.md). Debian's base build
  dated November 16 already carries the fixed `zlib1g` (`1:1.3.dfsg+really1.3.1-1+deb13u1`),
  but neither the `debian` nor the `hexpm/elixir` image for it was on Docker Hub
  yet. The next base refresh picks it up.
- Debian advisories since the previous pass (DSA-6614-1 to DSA-6633-1) are all for
  packages that are neither in the slim base nor installed by the runner stage
  (`ca-certificates`, `libssl3t64`, `libstdc++6`), including c-ares (DSA-6626-1).

## Compatibility

Guardian itself is unchanged. These are the cloudflared changes between 2026.10.7 and
2026.11.0
([release notes](https://github.com/cloudflare/cloudflared/blob/2026.11.0/RELEASE_NOTES)):

- VULN-170057: don't bypass Access with matrix parameters.
- Go 1.27.4.
- A logger correction and a CI change for Windows, neither affecting the connector.

## Product spec impact

None. No statements in `docs/product/overview.md` or `docs/product/spec.md` change.

## Validation

- The SHA-256 checksums of the downloaded `cloudflared-linux-amd64` and
  `cloudflared-linux-arm64` binaries match the release's published checksums.
- No Docker build was run, since the development machine has no container runtime.
  Fly's builder builds the image at deploy.
- The pre-commit gate passed: formatting, Credo, compiling with warnings as errors,
  and the full default suite, plus the cluster and lifecycle tests.

## Deploy notes

None beyond the standard deploy. After a separately authorized deployment, check:

- The build log shows the cloudflared 2026.11.0 download passing its checksum.
- `GET /health` returns 200, and a request without a key gets 401.
- When `TUNNEL_TOKEN` is set, the connector registers its tunnel connections.

Don't inject test events. Roll back to the previous image if Guardian fails to come
up.
